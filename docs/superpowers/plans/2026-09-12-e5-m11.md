# Plano — E5 M11: CI/CD e Infraestrutura como Código

## Objetivo

Quinto módulo do Nível 2. Spec (`content/levels.yaml`): discutir pipelines e
IaC em conversa e em PR, descrever falhas e estratégias de rollout.
Competências VOC/SPK/WRI; pré-requisitos M06+M10; conclusão "Padrão".
M11-05 é `[SIM]` — revisão de mudança de pipeline + discussão de rollout.

## Tarefas

- **T1** — `module.yaml` (pass padrão) + `tests/lessons-m11.test.ts`.
- **T2** — 4 padrões BR novos com guardas de FP (tags `vocab.ci`/`vocab.iac`
  já existem — nenhuma tag vocab nova):
  - `depends in` → depends on (protege "depends in part on")
  - `suggested me to` → suggested I / suggested that (suggest não leva
    objeto indireto direto)
  - `apply the terraform` → run terraform apply / apply the config
    (protege "terraform apply" na ordem do comando)
  - `the deploy was succeeded` → the deploy succeeded (verbo intransitivo
    não leva passiva; protege "was succeeded by")
- **T3–T7** — 5 aulas (M11-05 = simulação: diálogo ≥ 10, listening 8,
  fala 60 s, pré-requisitos nas quatro aulas):
  - M11-01 vocabulário de pipelines: stage, job, artifact, runner, trigger,
    flaky, gate
  - M11-02 descrevendo falhas de pipeline e como corrigiu
  - M11-03 Terraform/IaC em conversa: plan, apply, drift, state, it wants
    to recreate
  - M11-04 estratégias: trunk-based, feature flags, blue/green, canary,
    rollback
  - M11-05 revisão de mudança de pipeline + discussão de rollout
- **T8** — avaliação: 15 itens cobrindo as tags `gram/br/vocab` reais +
  variantes.
- **T9** — validação via API na cópia, `AGENTS.md`, resultado no plano.

## Riscos

- `depends in` precisa do guard de "in part" — "depends in part on" é
  inglês correto.
- `was succeeded` exige guard de "by" — "was succeeded by" é passiva
  legítima.
- `apply the terraform` — só quando "apply" precede "terraform" como verbo;
  o comando "terraform apply" fica fora por construção.
