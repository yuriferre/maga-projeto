# Plano — M13 E-mails e documentação (Nível 2)

Spec: `docs/planejamento/02-trilha.md` (M13) + `content/levels.yaml`.
Descoberta: o Nível 2 tem **8 módulos (M07–M14)**, não 6 — a avaliação de
nível (`level-2.yaml`, rascunho em `/tmp/level-2-draft.yaml`) só entra
depois de M14.

- **Objetivo:** e-mails profissionais, README e runbook claros.
  **Competências:** WRI. **Pré-requisitos:** M03, M06.
- **Conclusão:** padrão + os 2 textos finais ≥ 4/5 → `writingMin: 4` na
  avaliação do módulo (mesmo precedente do `writingMin: 3.5` de M03/M09).
- **M13-05 = prática** (1 e-mail de escalada + 1 runbook) — formato
  integração.

## Tarefas

- **T1** — `module.yaml` (competências [WRI], pré-requisitos M03+M06,
  pass `writingMin: 4`) + `tests/lessons-m13.test.ts`.
- **T2** — 4 padrões BR novos + tags (`gram.formal-register`,
  `vocab.email-docs` novas) + testes RED:
  - `please find in attachment` / `in attachment` → attached
    (protege "in the attachment" — com artigo é legítimo)
  - `best regrets` → best/kind regards (fecho clássico)
  - `I wait your reply` → I look forward to / I await
    (protege "I await your reply" e "I'll wait for your reply")
  - `sorry for late` → sorry for the delay / sorry I'm late
    (protege "sorry for the late reply")
- **T3–T7** — 5 aulas:
  - M13-01 anatomia do e-mail: assunto, abertura, corpo, fecho; formal ×
    neutro; o que soa traduzido
  - M13-02 e-mails comuns: pedido, follow-up, agendamento, escalada,
    gentle reminder
  - M13-03 README: estrutura, imperativo, exemplos, Note/Warning
  - M13-04 runbooks: pré-condições, passos numerados, verificação,
    rollback, quem chamar
  - M13-05 [prática] e-mail de escalada + runbook completo
- **T8** — avaliação: 15 itens cobrindo as tags reais + variantes.
- **T9** — validação via API na cópia, `AGENTS.md`, resultado no plano.

## Riscos

- `in attachment` — só sem artigo; "in the attachment" é inglês válido.
- `sorry for late` — exigir "for late" adjacente para não pegar "sorry
  for the late reply".
- `I wait` — só o presente simples nu; "I await" é formal legítimo.

### Desvios

- A spec pede "2 textos finais ≥ 4/5" — o motor tem uma nota de escrita
  só; a avaliação pede as duas peças num texto único separado por `---`
  (mesmo desvio de M03/M09, documentado).
- `writingMin: 4` fica na avaliação do módulo (`module.yaml` pass) —
  aulas seguem `writingMin: 3` (o helper `checkLesson` fixa 3).
- Dois testes RED ajustados: "sorry for the late." virou "sorry about
  late" (o padrão só dispara sem artigo) e o reorder do M13-03 precisou
  de token "the" duplicado.
- Blocos `brErrors` das aulas só aceitam tags existentes no catálogo —
  M13-03/04 reutilizam padrões reais (third-person-s, it-not-works,
  revert-back, verify-if…).
