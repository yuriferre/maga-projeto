# E6 — Adaptação e checkpoints

Spec: `docs/planejamento/01-plano-geral.md` — "Tags fracas → warm-up e recomendação; checkpoint de 4 semanas; export/import". Aceite: errar de propósito uma tag e ver o warm-up seguinte refletir; exportar e importar sem perda.

## O que já existe (não refazer)

- `weakTags` (server/warmup.ts): erro > 40 % com ≥ 3 tentativas em 30 d, ou ≥ 3 erros em 7 d — regra da spec.
- `selectWarmup`: até 3 itens de tags fracas + revisão por tempo (3/7/21 d) — o aceite "errar uma tag e ver o warm-up refletir" já funciona; só falta teste explícito.
- Timeline já rotula `checkpoint`; `assessments.kind` já aceita `'checkpoint'` no CHECK.
- Heatmap de tags no painel (sem clique).

## O que falta

1. **Recomendação diária** — spec: "'revisar tag X' ou 'refazer exercícios de aula Y' antes de avançar, quando houver ≥ 2 tags fracas ligadas à próxima aula".
2. **Checkpoint de 4 semanas** — mesmo formato do teste inicial para comparação direta (linha do tempo).
3. **Export/import** — dump JSON de todas as tabelas + restore validado, sem perda.
4. **Exercícios extras por tag** — spec do painel: "clique leva a exercícios extras da tag"; fecha o ciclo de adaptação.

## Tarefas

### T1 — Recomendação no painel

- `nextLesson(content, db)`: primeira aula com conteúdo não concluída na ordem da trilha (nível → módulo → aula).
- `recommendation` em `buildDashboard`: se a próxima aula tem ≥ 2 tags fracas → `{ kind: "review-lesson", lessonId, tags }` ("refaça exercícios de Y — tags fracas X, Z"); senão, se há tags fracas → `{ kind: "review-tag", tag }` (a com mais erros); senão `{ kind: "next", lessonId }`.
- Card no Dashboard acima do grid.
- Testes: :memory: com tentativas semeadas cobrindo os três casos.

### T2 — Exercícios extras por tag (`/tags/:tag`)

- Heatmap: chip vira `Link` para `/tags/:tag`.
- Página `TagDrill.tsx`: lista exercícios de todas as aulas com conteúdo que carregam a tag, agrupados por aula de origem; um `ExerciseList` por aula com `block="warmup"` (a tentativa pertence à aula de origem — "refazer exercícios", alimenta as stats da tag).
- Sem mudança de schema/DB: `warmup` já está no CHECK e no `BlockSchema`.

### T3 — Checkpoint de 4 semanas

- `checkpointDue(db, now)`: 28 d após a última avaliação `placement` **ou** `checkpoint`.
- Rotas `/api/checkpoint/{state,writing,speaking,finish}` espelhando `/api/placement/*`: mesmo conjunto de exercícios (`placementExercises`), mesmo `computePlacementResult` → comparação direta na timeline; `ref: "checkpoint"`.
- `/api/attempts`: aceita `lessonId: "checkpoint"` com `block: "placement"` e o mesmo conjunto de ids (já permitido pelo CHECK do DB).
- `Placement.tsx`: extrair o fluxo para componente compartilhado recebendo a superfície de API; `Checkpoint.tsx` o reusa. Banner no painel quando `due` (`CheckpointCard` ou dentro do PlacementCard).
- Testes: due aos 28/27 d, fluxo completo via `app.request`, `kind: "checkpoint"` gravado, timeline o inclui.

### T4 — Export/import

- `GET /api/export` → `{ version: 1, exportedAt, tables: { attempts: [...], lesson_progress: [...], writing_submissions, speaking_sessions, srs_cards, srs_reviews, assessments, weekly_goals, study_sessions, settings } }` (todas as colunas, `schema_version` fora).
- `POST /api/import` → body validado com zod; `delete` nas tabelas em ordem FK-segura + `insert` preservando ids e timestamps. Resposta com contagens.
- UI: botões no painel (exportar baixa JSON; importar via `<input type=file>` + confirm).
- Teste de aceite: semear banco → export → importar em banco novo → export de novo → JSONs iguais ("sem perda").

### T5 — Aceite do warm-up + docs + fechamento

- Teste explícito do aceite: errar 3× uma tag → `weakTags` a contém → `selectWarmup` da aula seguinte traz item daquela tag.
- Atualizar `AGENTS.md` (E6 entregue, MVP completo E0–E6).
- `pnpm test`, `typecheck`, `build`; validação manual via API na cópia do banco.

## Riscos / decisões

- **Reuso do placement no checkpoint**: mesmo YAML e mesmo motor → comparação direta é verdadeira; o custo é o usuário rever os mesmos itens (aceitável — é a medida da spec).
- **Bloco `placement` para o checkpoint**: o CHECK do DB já aceita; `/api/attempts` passa a aceitar `lessonId="checkpoint"` com o mesmo conjunto. Sem migração.
- **Export é dump JSON, não cópia do arquivo .sqlite**: portável, validável com zod, e exercita o caminho "sem perda".
- **Ref `checkpoint` fixo** (não `checkpoint-2` etc.): a janela de run usa "desde o último checkpoint", igual ao placement; cada checkpoint vira uma linha na timeline.

## Fora de escopo

- Exercícios adaptados gerados por LLM (E4 está fora do roteiro).
- Comparação visual radar checkpoint × teste inicial — a timeline já mostra nível/% de cada um.

## Resultado (2026-09-12)

Implementado na `feat/e6`:

- `server/recommend.ts` + campo `recommendation` no dashboard: `nextLessonId` (primeira aula com conteúdo não concluída), `review-lesson` quando ≥ 2 tags fracas ligadas à próxima aula (alvo = aula concluída que mais cobre essas tags; fallback a própria próxima), `review-tag` com a mais errada, senão `next`. Card "Hoje:" no painel.
- `/tags/:tag` (`TagDrill`): exercícios da tag agrupados por aula de origem, `ExerciseList` com `block="warmup"`; chips do heatmap viram links. Sem mudança de schema.
- Checkpoint: `checkpointDue` (28 d após a última avaliação placement/checkpoint), rotas `/api/checkpoint/{state,writing,speaking,finish}` reusando `placementExercises` + `computePlacementResult`; `/api/attempts` aceita `lessonId="checkpoint"` com `block="placement"` e os ids do teste inicial; `PlacementFlow` compartilhado entre `Placement.tsx` e `Checkpoint.tsx`; banner de vencimento no `PlacementCard`; timeline já rotulava `checkpoint`.
- Export/import: `server/transfer.ts` — `GET /api/export` (dump JSON das 10 tabelas, ids/timestamps preservados) e `POST /api/import` (zod + colunas conferidas + delete em ordem FK-reversa + insert transacional); `DataCard` no painel com download e `<input type=file>` + confirm.
- Aceite explícito: teste "errar 3× uma tag → `weakTags` lista → warm-up traz item dela".

### Desvios

- "Refazer exercícios de aula Y": o alvo é a aula **concluída** que mais cobre as tags fracas da próxima aula (a spec não diz qual aula); fallback = a própria próxima aula.
- Exercícios do teste inicial ficam fora do drill por tag (bloco `placement` é exclusivo das avaliações placement/checkpoint).
- `GET /api/export` expõe o banco inteiro sem autenticação — coerente com "uso pessoal, um usuário" do spec.

### Validação

- **510/510 testes** (36 arquivos) · typecheck e build limpos.
- Aceite export: export → import em banco novo → export igual (round-trip testado); restore substitui (não faz merge); rejeita versão desconhecida e colunas inexistentes (400).
- API na cópia do banco: `checkpoint/state` (due=false, nextAt +28d do último placement), `export` com contagens reais (200 attempts, 8 assessments), dashboard com `recommendation` e `checkpoint`.
- UI sem teste automatizado — verificar `/` (recomendação, banner de checkpoint, DataCard), `/tags/br.doubt`, `/checkpoint`.
