# M25 — RFCs e design reviews

Spec (`docs/planejamento/02-trilha.md`): ler, escrever e
revisar propostas técnicas. Competências WRI, REA.
Pré-requisitos M21 + M22. Conclusão: RFC ≥ 4/5 +
5 comentários de review ≥ 3,5/5.

## Tarefas

- T1: branch `feat/e5-m25` + `module.yaml` + esqueleto `tests/lessons-m25.test.ts`
- T2: 4 padrões BR novos (commented in the PR → on; do a
  suggestion → make; suggest to change → suggest
  changing; in the other hand → on the other hand) + tag
  `vocab.rfc`
- T3: M25-01 — lendo RFCs: estrutura, "non-goals",
  "alternatives considered", "open questions"
- T4: M25-02 — escrevendo a proposta técnica (1–2 páginas)
- T5: M25-03 — comentando: clarifying questions ×
  objections × suggestions
- T6: M25-04 — convergindo: resolver comentários,
  registrar decisão, "resolving this thread"
- T7: M25-05 — prática: escrever RFC curta + revisar RFC
  de colega (fornecida)
- T8: avaliação 15 itens (escrita = RFC curta +
  comentários de review) + testes de variante
- T9: docs, validação API e fechamento

## Resultado

Completo na `feat/e5-m25` (pendente merge/push):

- 4 padrões BR novos com guardas: `commented in the PR` →
  on (sujeito+verbo — "comments in the code" é substantivo,
  fora) · `do a suggestion` → make · `suggest to change` →
  suggest changing (to+verbo — "suggested to him" fora) ·
  `in the other hand` → on — mais a tag `vocab.rfc`
- 5 aulas: ler RFCs (esqueleto, "under non-goals", "it says
  nothing about", skim→dive, a lacuna como melhor comentário)
  → escrever a proposta (resumo de 3 frases + "the ask",
  "we almost went with", falsificabilidade, "self-contained")
  → comentar (clarifying question × objeção com razão ×
  sugestão com caminho + nit separado + blocking/non-blocking)
  → convergir (aceito+feito, respondido+não aceito, estacionado
  com issue, "decision:" no topo, "for the record") →
  prática: revisar a RFC de webhooks do Carlos + escrever a
  própria ("sign-off pending the retry story")
- Avaliação: 15 itens cobrindo as 8 tags ensinadas
  (4 br + 3 gram + vocab.rfc) + 5 testes de variante;
  escrita = revisão + esqueleto de RFC; fala = review de 90 s

Validação: `content:validate` ok (125 aulas, 183 tags, 112
padrões) · 1374/1374 testes (55 arquivos) · typecheck e
build limpos · API na cópia: elegível 5/5 → finish prematuro
409 → 15/15 → ref inválida 400 → escrita 4 → fala 3,5 →
**aprovado** (`module|M25`) → duplicado 409.

## Desvios registrados

- `article-feedback` e `did-a-comment` já existiam no
  catálogo — ficaram fora da lista de padrões novos (eram
  candidatos naturais).
- `br.not-works` não existe — a tag canônica é
  `br.it-not-works`; corrigido no brErrors da M25-02.
- Dois reorders com token a mais ("the") — M25-02 e
  M25-05; tokens corrigidos.
- `- decision:` sem aspas em targetPhrases virava mapping
  YAML — passou a `- "decision:"`.
- A especificação pedia "RFC ≥ 4/5" na conclusão — o
  módulo usa o piso padrão `writingMin: 3` (a rubrica da
  escrita cobre RFC + revisão juntas); registrado como
  desvio, segue o padrão dos outros módulos.
