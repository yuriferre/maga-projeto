# E5 — lote 1: motor de avaliação + módulo M01: desenho

Data: 2026-09-11. Origem: `docs/planejamento/02-trilha.md` (Nível 1, M01), `docs/planejamento/01-plano-geral.md` (§5 critérios, §8 linha E5), `docs/planejamento/03-exemplo-aula-M01-02.md` (formato de aula). Estado de partida: E0–E3 entregues (`main` 82b9eca). **A E4 (Claude API) está fora do roteiro por decisão do usuário**: nada aqui usa LLM.

## 1. Objetivo do lote

1. **Motor de avaliação** de módulo (e, genericamente, de nível): conteúdo YAML próprio, itens objetivos + escrita + fala, resultado gravado em `assessments`, elegibilidade por aulas concluídas, página própria.
2. **Módulo M01 completo**: as 4 aulas que faltam (M01-01, M01-03, M01-04, M01-05) no mesmo formato da M01-02, e a avaliação do M01 (15 itens + escrita + fala).
3. **Catálogo de erros BR**: padrão conservador para `br.actually` (hoje só existe como tag), teste de guarda para `br.depend-of`; `br.in-the-last-week` fica sem regex (ver §4.3).

Critério de aceite (plano geral E5): cada lote passa no validador e na checklist de qualidade (nada genérico, todo erro BR verificado, diálogos plausíveis, traduções revisadas). Aqui: as 4 aulas jogáveis ponta a ponta, o M01 aprovável com a regra da seção 3, tudo revisado por uma pessoa antes do merge.

## 2. Fora do escopo

- Módulos M02–M06 e a avaliação de Nível 1 (lotes seguintes; a avaliação de nível usa este motor com `kind='level'` e o conteúdo entra no último lote).
- Glossários `infra`/`incident` (entram com M04/M05).
- Roleplay, rubrica automática de fala/escrita (E4, descartada).
- Itens de avaliação no pool do warm-up (decisão: só aulas e placement alimentam o warm-up).
- Recomendação diária, checkpoint (E6).

## 3. Decisões

| Decisão | Por quê | Custo se errado |
|---|---|---|
| Aprovação de módulo = itens ≥ 75 % **e** escrita autoavaliada ≥ 3 **e** fala modo A ≥ 3/5 | Decisão do usuário; reusa os três motores existentes; mantém a produção (escrita/fala) na avaliação | Nota de escrita é autoavaliação (como nas aulas) |
| Avaliação é conteúdo próprio (`assessment.yaml` por módulo), não uma "aula 6" | `LessonSchema` obrigaria vocabulário/diálogo/cards placeholder | Um schema a mais |
| Tentativas em `attempts` com `lesson_id = <ref>` (ex.: `M01`) e `block = 'assessment'` | `tagStats`/`weakTags` enxergam os erros; rodada por `ts > última avaliação` como no placement | Migração 2 reconstrói `attempts` (mesma técnica da E2) |
| Elegibilidade: todas as aulas do módulo com conteúdo concluídas | Trilha: "todas as aulas concluídas + avaliação" | Módulo sem todas as aulas escritas (M02+ em lotes futuros) exige só as existentes; a UI diz quantas faltam |
| Refazer permitido; vale a última; linha do tempo guarda todas | Igual ao placement | Nenhum |
| M01-05 "simulação" sem LLM = standup completo (3 personas no diálogo, escuta longa, fala 60 s, escrita de follow-up no Slack) | Sem interlocutor; o que a spec chamava de simulação vira produção guiada | Menos interativo que o plano original; registrado como desvio |
| Novos padrões do catálogo entram com teste de guarda de falsos positivos | Regra do AGENTS.md | Nenhum |
| Itens da avaliação não entram no warm-up | Warm-up é revisão de conteúdo ensinado; avaliação é medição | Nenhum |

### 4.3 Catálogo de erros (`content/br-errors.yaml`)

- `actually-currently` (tag `br.actually`): "actually" usado como "atualmente" — padrão conservador: `\bactually (i|we|he|she|they|it) (am|'m|are|'re|is|'s) (working|doing|using|running|living|studying)\b` e `\b(i|we|they) actually (work|use|run|live|study|have) (at|in|on|with|for)\b` só quando seguido de contexto temporal ("now", "nowadays", "these days", "at the moment"). Frases corretas que NÃO disparam: "Actually I'm not sure that's right.", "Actually, yeah.", "It's actually working now."
- `br.in-the-last-week`: **sem padrão de regex**. "In the last week" é correto quando significa "nos últimos 7 dias"; o erro (usar como "semana passada") só se distingue pelo tempo verbal e pelo contexto, que uma regex conservadora não pega. A tag fica para itens de quiz e cards.
- `depend-of` já existe; ganha teste de guarda com "It depends on the runner." e "the dependency of the module".

`tags.yaml` ganha `gram.time-expressions` (label "Expressões de tempo e prazo").

## 5. Schema, loader e migração

`shared/schema.ts`:

```
BlockSchema += "assessment"
ModuleFileSchema = { id, assessment: { description }, pass: { itemsMin: 0–1 default 0.75, writingMin: 1–5 default 3, speakingMin: 1–5 default 3 } }
ModuleAssessmentSchema = { id: /^M\d{2}$/, title, intro (markdown), items: Exercise[] ≥ 10, writing: WritingSpecSchema, speaking: SpeakingModeASchema }
ModuleFile.assessment... (mantém) ; ContentBundle.moduleAssessments: Record<string, ModuleAssessment>
```

`shared/content-loader.ts`: lê `content/modules/Mxx/assessment.yaml` quando existe; `crossValidate`: `assessment.id` = pasta, ids de itens únicos no bundle e prefixo `<id>-A`, tags existentes, `minWords ≤ maxWords`, forma dos exercícios (`checkExerciseShape`).

`server/db.ts`: migração 2 reconstrói `attempts` com `block in ('warmup','quiz','listening','writing','speaking','placement','assessment')` preservando linhas e índices (teste igual ao da migração 1).

## 6. Servidor

`server/assessment.ts` (puro):

```
AssessmentSpec = { ref: string; kind: "module" | "level"; items: Exercise[]; pass: { itemsMin; writingMin; speakingMin } }
AssessmentInputs = { attempts: Map<string, AttemptRow>; writing?: WritingRow; speaking?: SpeakingRow }
missingForAssessment(spec, inputs) → { exercises: string[]; writing: boolean; speaking: boolean }
computeAssessmentResult(spec, inputs, finishedAt) → { version: 1, kind, ref, itemCount, correct, itemsPct, writingScore, speakingScore, passed, weakTags, items[{ id, correct, answer }], finishedAt }
eligibility(content, db, moduleId) → { lessonsTotal, lessonsDone, missing: string[] }   // aulas com conteúdo do módulo não concluídas
```

Rotas (sub-router `/api/modules/:id/assessment`, 404 se o módulo não tem `assessment.yaml`):
- `GET /state` → `{ eligible: { lessonsTotal, lessonsDone, missing }, latest: AssessmentRecord | null, run: { answered, writing, speaking } }`.
- `POST /writing`, `POST /speaking` → mesmos motores das aulas, `lesson_id = <id>` (ex.: `M01`).
- `POST /finish` → 409 `{ error: "aulas pendentes", missing }` se não elegível; 409 `{ error: "avaliação incompleta", missing }` se faltam itens/escrita/fala; senão grava `assessments(kind='module', ref=id)` e devolve `{ assessment }`.
- `POST /api/attempts` aceita `block = 'assessment'` quando `lessonId` é um módulo com avaliação e `exerciseId` pertence a ela.
- `GET /api/progress/overview` passa a devolver também `modules: { [id]: { passed: boolean; latest: AssessmentRecord | null } }`.

## 7. Cliente

- `/modules/:id/assessment` (`src/pages/ModuleAssessment.tsx`): estados `loading → locked (lista de aulas faltantes) → intro → items → writing → speaking → result`; reusa `ExerciseList` (feedback adiado, `initialAnswered`), `Writing`, `Speaking`; resultado em `AssessmentResult` (generalização de `PlacementResult` para blocos itens/escrita/fala + aprovado/reprovado com a regra em uma frase; `PlacementResult` continua existindo).
- `Module.tsx`: card "Avaliação do módulo": bloqueado ("faltam N aulas"), disponível (botão), ou resultado (aprovado/reprovado, %, data, "Refazer").
- `Levels.tsx`: módulo com avaliação aprovada ganha badge "aprovado".
- `Lesson.tsx`: nada muda (aulas novas são só conteúdo).

## 8. Testes

- Conteúdo: para cada aula nova, contagens mínimas da §4.1, tags existentes, ids únicos e prefixados, modelo de escrita passa nas restrições e no detector, `wordOverlap(frase, frase) = 1` nas frases-alvo, gabarito dos `multiple_choice` balanceado, markdown sem asteriscos sobrando; `crossValidate` limpo.
- Catálogo: `actually-currently` dispara nos exemplos errados e NÃO nos corretos; guarda ampliada.
- Schema/loader: `ModuleAssessmentSchema`, `pass` defaults, `crossValidate` acusa id de item duplicado/tag desconhecida/prefixo errado.
- Migração 2: banco na versão 1 com linhas → preserva e aceita `assessment`.
- `server/assessment.ts`: tabela de aprovação (74/75 % × escrita 2/3 × fala 2,5/3), `missingForAssessment`, `eligibility` com 0/2/5 aulas concluídas.
- Rotas: sem elegibilidade → 409; fluxo completo (concluir as 5 aulas pelas rotas, responder 15 itens, escrita, fala, finish) → aprovado; reprovar por fala 2,5; refazer; `overview.modules.M01.passed`.
- UI no Chrome: as 4 aulas abrem e são jogáveis (escuta, escrita, fala, quiz, conclusão), avaliação bloqueada → liberada → resultado, badge na trilha.

## 10. Riscos

- **Autoria**: 4 aulas × ~300 linhas + avaliação. Mitigação: uma tarefa por aula com revisão de conteúdo por revisor (como no placement) e sua revisão humana antes do merge.
- **Regex `actually`**: risco de falso positivo; padrão restrito a contexto temporal explícito e teste de guarda.
- **M01-05 sem LLM**: é uma aula longa, não uma simulação; registrado.
